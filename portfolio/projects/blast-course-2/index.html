Engineering Systems

Polymorphic Projectile Architecture

To keep projectile behavior predictable at high speeds, I bypassed Unreal Engine's native UProjectileMovementComponent and built a custom, Tick-driven movement system using SweepSingleByChannel.

  • Material-Based Collisions: Environmental interactions are handled without extra actor components by detecting "Defuser" surfaces directly via UMaterialInterface.
  • Polymorphic Extensions: ABaseRocket lets child classes (such as Bounce or Remote rockets) implement custom behaviors like vector reflection simply by overriding the virtual Impact() method.
  • Decoupled Lifecycle: Rockets have zero awareness of the object pool, they simply execute their lifecycle and broadcast an OnRocketFinished multicast delegate when ready to be reclaimed.

Dual Object Pooling

Repeatedly spawning and destroying rockets and explosions at runtime introduces memory fragmentation and garbage collection spikes. To keep frame times stable, I implemented two pooling strategies inside ACustomGameMode.

  • O(1) Circular Buffer: Short-lived explosion effects don't require lifecycle tracking, so they use a modulo-based ring buffer for constant-time reuse.
  • Active/Free Queues: Rockets require stricter state tracking and are managed through separate active and free TArray queues.
  • Aggressive Recycling Failsafe: If the pre-allocated free pool runs out, the system forces the oldest active rocket to detonate and recycles it immediately, preventing mid-combat allocations or hitches.
ACustomGameMode.cpp 
ABaseRocket* ACustomGameMode::AcquireRocketFromPool(ERocketType _eType) {
    FRocketPool& rPool = m_mRocketPools[_eType];
    TObjectPtr<ABaseRocket> pRocket = nullptr;

    if (!rPool.Free.IsEmpty()) pRocket = rPool.Free.Pop();
    else if (rPool.Active.Num() > 0) {
        // Aggressive recycling: force oldest active rocket to explode
        pRocket = rPool.Active[0];
        rPool.Active.RemoveAt(0);
        pRocket->ForceExplosion();
    }

    return pRocket.Get();
}

Extended UMG Architecture

Enforcing exact pixel dimensions and aspect ratios in C++ while keeping a live WYSIWYG workflow for UI artists in the Unreal Editor requires working around UMG's native layout rules. I built an extended widget hierarchy to handle sizing and visibility cleanly in code.

  • Recursive Visibility Propagation: The base UCustomUserWidget propagates custom ShowWidget() and HideWidget() calls recursively down nested widget hierarchies.
  • Live Editor Aspect Locking: UResizableUserWidget overrides SynchronizeProperties() so that when a UI artist resizes a widget in the editor, C++ detects the driving axis and updates the opposing dimension in real time to preserve its aspect ratio.
  • Encapsulated Leaf Widgets: Base wrappers like UCustomButtonWidget map custom C++ state logic directly to native ESlateVisibility states.
UResizableUserWidget.cpp 
void UResizableUserWidget::SynchronizeProperties() {
    Super::SynchronizeProperties();

    // Preserve aspect ratio if the flag is enabled in the editor.
    if (m_bPreserveAspectRatio) {
        if (m_fAspectRatio < 0.f && m_vWidgetSize.Y != 0.f) {
            m_fAspectRatio = m_vWidgetSize.X / m_vWidgetSize.Y;
        }

        ApplyAspectRatio();
    } 
    else m_fAspectRatio = 0.f;

    SetWidgetSize(m_vWidgetSize);
    UpdateSizeToContent();
    m_vLastSize = m_vWidgetSize;
}
